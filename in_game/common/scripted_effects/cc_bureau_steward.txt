# The bureau steward: setting and clearing the per-bureau assignment.
#
# Called by cabinet_actions/cc_duty_bureau_steward.txt. See that file for the design; the short
# version is that a minister takes charge of ONE named bureau, which then costs less and works
# better, and no other bureau changes.
#
#
# WHY THIS IS A LONG LIST OF NEAR-IDENTICAL BRANCHES.
#
# Both payloads have to name a bureaucracy type literally:
#
#   the cost discount   sets cc_steward_<type>, which that bureaucracy's own
#                       maintenance_price_modifier reads. It has to be per-type because
#                       maintenance_price_modifier is evaluated in COUNTRY scope
#                       (bureaucracies/readme.txt) and cannot ask which bureau it is pricing.
#
#   the impact bonus    grants cc_steward_impact_<type>, a static modifier carrying that
#                       bureaucracy's own <type>_impact_modifier key. It CANNOT grant the
#                       impact type directly: that is a modifier type, not a static modifier,
#                       and add_country_modifier reads only the latter. Getting this wrong is
#                       a load error, not a silent no-op. See
#                       main_menu/common/static_modifiers/cc_bureau_steward_impact.txt.
#
# There is no dynamic variable naming in this engine and no way to derive either name from a
# scope, so the branch list is the only available shape. It is generated against the same key
# list as zzz_cc_vanilla_bureau_overrides.txt and the two must stay in step: a type present in
# one and absent from the other fails silently, with the tooltip still promising a discount.
#
#
# WHAT IS DELIBERATELY NOT COVERED. The Rhomania submod's three own bureaucracies
# (cc_byz_genikon, cc_byz_epi_ton_deeseon, cc_byz_oikeioi) are absent, because the main mod
# cannot name types that only exist when an optional submod is loaded: referencing an undefined
# bureaucracy_type is a load error, and this file has to parse for everyone. Those three are
# stewardable only if the submod ships its own action for them. The vanilla Byzantine TEN are
# covered here, since those types exist with or without the submod.

# ---- Thread state ----
#
# Initialised lazily, like every other score in this mod, so a save from before the thread
# existed backfills on first contact instead of erroring. change_variable on an unset variable
# errors inside an effect with a blank message, which is why this runs at the top of every
# event's immediate rather than once at game start.
#
#   cc_bureau_venality  0..5  how far offices have become property rather than posts
cc_init_bureau_scores_effect = {
	if = {
		limit = { NOT = { has_variable = cc_bureau_venality } }
		set_variable = { name = cc_bureau_venality  value = 0 }
	}
}
