# The steward's impact bonus: one static modifier per bureaucracy.
#
# WHY THIS FILE EXISTS, AND IT IS A CORRECTION.
#
# The steward effect originally did this:
#
#     add_country_modifier = { modifier = cc_scholarly_concordat_impact_modifier ... }
#
# and the game refused it at load with
#     PostValidate of effect 'add_country_modifier' returned false
#
# <name>_impact_modifier is a MODIFIER TYPE, not a static modifier. Modifier types are the
# individual keys you write INSIDE a modifier block; add_country_modifier takes the name of a
# static modifier, which is a named bundle of such keys. The two live in different namespaces
# and the engine will not substitute one for the other.
#
# The confusion was easy to fall into and worth recording. All 34 impact types are registered
# by vanilla, so grepping for the name found it and the reference looked resolved. It was
# resolved, as a type, in a namespace add_country_modifier does not read from. Vanilla appears
# to offer a precedent in flavor_pol.txt:2406, which grants
# piotrokow_wislica_statutes_impact_modifier by name, but that is an ordinary static modifier in
# country.txt:8120 that merely shares the suffix. It is not a bureaucracy impact type at all.
#
# So: one static modifier per bureaucracy, each carrying that bureaucracy's own impact type.
# This is the layer that was missing, not a workaround.
#
#
# 0.15 ON EVERY ONE, deliberately uniform. The steward is the same person doing the same job
# whichever office he is sent to, and a per-bureau table of values would be a balance surface
# nobody asked for. The interesting choice is WHICH bureau, not how much.
#
# The list must stay in step with scripted_effects/cc_bureau_steward.txt and with the override
# files. A bureaucracy present in one and absent from another fails silently.

# board_of_revenue_bureaucracy
cc_steward_impact_board_of_revenue_bureaucracy = {
	game_data = {
		category = country
	}
	board_of_revenue_bureaucracy_impact_modifier = 0.15
}
