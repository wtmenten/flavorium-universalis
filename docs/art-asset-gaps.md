# Art asset gaps

Every mod-defined key that resolves an image by naming convention, and whether that image
exists. Generated by auditing each `common/` content type against the vanilla art path it
resolves to, cross-checked against `logs/error.log`.

Totals: **397 content keys resolve to art that does not exist**, spread across 17 content
types. Situations and IOs need two files each, so that is roughly **494 image files**, of
which 90 are Rhomania mission task icons and one is an event background. A further 18 events
carry no art direction at all, and one shipped asset is malformed.

## How EU5 resolves art

There is no `.gfx` sprite declaration step. Nothing in vanilla declares `icons/traits` or
`icons/modifier_types` in a `.gfx` file; the engine derives the path from the content type and
the entry key. Two consequences:

1. Dropping `main_menu/gfx/interface/icons/traits/my_trait.dds` into the mod is the entire
   wiring step for a trait icon. No registration.
2. A typo in the key means silent fallback, not an error.

Most directories ship a `_default.dds`, so a missing file degrades to a generic placeholder
rather than a pink box. The exceptions matter, and are listed under "Hard gaps" below.

`main_menu/gfx/...` is the correct root for all of these, including art consumed in-game.
Vanilla and the D008 DLC both do it that way; `in_game/gfx/interface/icons/` does not exist in
vanilla at all.

### Explicit overrides

Only three content types accept an explicit `icon =` inside the entry, and each takes a bare
key that aliases another asset rather than a path:

| Type | Form | Resolves to |
|---|---|---|
| `generic_actions` | `icon = call_parliament` | `icons/generic_actions/call_parliament.dds` |
| `cabinet_actions` | `icon = cd_purge_cabinet_member` | `icons/cabinet_actions/<key>.dds` |
| Mission **tasks** | `icon = banking_advance` | `gfx/interface/advance/<key>.dds` |

Traits, situations, subject types, bureaucracies, laws, privileges, casus belli, character
interactions, IOs and parliament types take **no** `icon` key. Vanilla uses zero of them. The
filename is the only lever.

Aliasing is the cheap fix for most of this list: a `generic_action` can borrow any of the 125
vanilla generic-action icons, and a mission task can borrow any of the 1621 advance icons, at
zero asset cost.

### Rules that hold across every slot

**Compression.** BC1/DXT1 where there is no alpha (backgrounds, banners, the 64x90
strips). BC3/DXT5 where there is (every 128x128 icon, every cutout). Vanilla also ships
BC7 (`DX10` header, DXGI format 98) for newer or higher-fidelity assets; the engine reads
all three. BC7 doubles the file size over BC1 at the same dimensions, so use it only where
BC1 banding is visible.

**Mipmaps are mandatory.** The engine logs
`icondatabase.h:546 Streamed texture has no mipmaps` and streams the full-resolution
texture every frame. Generate the complete chain down to 1x1. This is the single most
common authoring mistake; see the malformed asset below.

**Power-of-two is not required.** 1080x440, 674x134, 64x90 and 1932x264 are all vanilla,
and all compress fine because each dimension is a multiple of 4 (the BC block size). Keep
both dimensions divisible by 4.

**Match the stated size exactly.** These are not "minimums". A situation background at
1280x720 is letterboxed or cropped against the panel, not scaled to fit.

**No BOM concerns.** The `.txt` BOM rule does not apply to binary assets.

### Converting

`tools/make_dds.py` implements all of the above. It knows every slot in the table by name, so
the size, compression, fit and destination folder come from one flag:

```
python tools/make_dds.py --list-slots
python tools/make_dds.py hero.png --slot trait --key war_hawk
python tools/make_dds.py art/traits/*.png --slot trait
python tools/make_dds.py bg.png --slot situation-bg --key cc_cabinet_court
python tools/make_dds.py x.png --slot situation-icon --key cc_byz_the_west --submod rhomania
python tools/make_dds.py --verify              # audit every DDS in the mod against its slot
python tools/make_dds.py --verify --fix-mips   # re-encode the ones that are wrong
```

It needs Pillow, and uses numpy when present. Output is byte-compatible with vanilla: a
128x128 BC3 icon comes out at exactly 21.5 KB with 8 mips, a 1080x440 BC1 background at
310.1 KB with 11, matching the vanilla files measured above.

Author at 2x or higher and let the tool downsample. It resizes in linear light with
premultiplied alpha, so soft-edged icons keep their colour at the edges instead of picking up
a dark fringe, and midtone contrast survives the mip chain.

`texconv -f BC1_UNORM -m 0 -y in.png` from DirectXTex does the same job if you prefer it
(`-m 0` for the full chain, `BC3_UNORM` for alpha), but it will not place the file or match the
slot sizes for you.

### Situations: backgrounds now present

Path: `icons/situations/<key>.dds` + `illustrations/situation/<key>.dds`  ·  128x128 / 1080x440  ·  1:1 / 27:11  ·  BC3 / BC1

`cc_cabinet_court`, `cc_subject_bonds`, `cc_byz_mamluk_confrontation` and `cc_byz_the_west`
now have their 1080x440 backgrounds. `cc_byz_the_west` still wants a 128x128 header icon.
`cc_balance_of_power` is complete; `cc_invasion_mexico` has both files but its background is
the malformed one above (1 mip, 1280x720 rather than 1080x440).

**A background file at the right path is not enough on its own.** The default
`block "situation_panel_image"` in `game/in_game/gui/panels/situation/common.gui:113` is the
only call site of `GetSituationIllustration(...)`, so a panel that overrides that block never
draws its illustration. All four panels above shipped a flat-colour gradient override and
ignored their art until the override was removed. Do not reintroduce one.

Both rhomania backgrounds live in the **main mod's** `main_menu/gfx/...` rather than the
submod's. That is safe, because the submod cannot load without the main mod, but it is worth
knowing when auditing the submod alone.
