# FRONT-END 2: the mission tree, for players with mission packs ON.
#
# 71 tasks. A spine with three braided pillars, five exclusive forks, four reconvergence
# points and seven optional spurs.
#
#
# READ THIS BEFORE ADDING A TASK.
#
# 1. REWARDS GO IN on_persistent_completion, NEVER on_completion. Per common/missions/
#    ____Info.txt, on_completion "is not executed if task_rewards_disabled is active in the
#    rules" while on_persistent_completion "is ALWAYS executed". The mission_rewards rule
#    defaults to only_end_mission_rewards, which sets task_rewards_disabled. Using
#    on_completion silently drops the reward under DEFAULT settings.
#
# 2. ONLY THE NINE CORNERSTONES HAVE A GENERIC-ACTION TWIN. Everything else is mission-mode
#    only and is not compensated for elsewhere. Mission packs are OFF by default; the
#    cornerstones and their permanent modifiers remain reachable either way, which is the part
#    that matters. See generic_actions/cc_byz_theatre_actions.txt.
#
# 3. Only ONE task may carry final = yes. That is cc_byz_task_mare_nostrum.
#
#
# THE FOUR STRUCTURES, and how each is expressed.
#
# ANY ORDER. Several tasks share one requires parent and reconverge later. The three western
# theatres all require only cc_byz_task_illyricum, so Italy, Africa and Spania can be taken in
# whatever order the map offers. This is also the historical order: Justinian took Africa in
# 533 and Italy afterwards, which the old strict chain forbade.
#
# RECONVERGENCE. requires = { a b c } is AND, so a task naming several parents waits for all
# of them. Vanilla does this (generic_conquer_province_mission_pack.txt:284, three parents).
#
# SUBSET (two of three). There is no count operator for mission_task_completed, so the test is
# an explicit OR of AND pairs wrapped in a custom_tooltip. The player reads one clean line and
# never sees the nine. Deliberately NOT done with a counter variable: a counter is derived
# state, bypassed tasks fire on_bypass rather than on_persistent_completion, and this tree
# bypasses a great deal (every fork sibling, every stone that can become impossible). A
# desynced counter would either unlock a branch early or block it forever with nothing in the
# log. mission_task_completed is stateless and reads the truth at every evaluation.
#
# EXCLUSIVE FORK. Five of them. Each sibling carries:
#     visible = { NOT = { mission_task_completed = mission_task:<other> } }
#     bypass  = { mission_task_completed = mission_task:<other> }
# The visible hides the road not taken, exactly as vanilla does at
# generic_capital_economy_mission_pack.txt:270. The bypass is load-bearing rather than
# cosmetic: without it a reconvergence naming either sibling would wait forever on the one
# that can no longer complete.
#
#
# BYPASS ON UNREACHABLE CONDITIONS. Any task depending on owning one specific place carries a
# bypass, because gating means one impossible stone would block its whole branch. Tasks whose
# condition only gets easier with time (a NOT-exists, an income threshold) need none.
#
#
# SHAPE
#
#   T0  House in Order      5 roots, any order
#   T1  Three pillars       Fisc / Faith / Sword, any order -> The State Restored (2 of 3)
#   T2  The Greek World     claimants, neighbours, FORK 1 Venice or Genoa
#   T3  Anatolia            FORK 2 destroy or vassalise the Turks, FORK 3 tagmata or pronoia
#   T4  The Levant          the seats (2 of 3), FORK 4 treaty or Pentarchy War
#   T5  The West            Illyricum -> Italy / Africa / Spania in ANY ORDER (2 of 3)
#   T6  The East            off the Sinai Road, FORK 5 monopoly or company
#   S   Spurs               7 optional, none gate anything
#
# ART. 71 icons are named and none are supplied. A missing .dds renders a BLANK button without
# logging, so this is checked by eye. Cornerstones and pillar capstones are worth doing first.
